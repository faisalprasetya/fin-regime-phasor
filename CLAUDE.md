# fin-regime-phasor

Research project: build complex-valued "phasor" features (magnitude = Parkinson volatility, phase = `2*arctan(k*R)` of frac-diffed log return) from financial bar data, feed into a Hidden Quantum Markov Model (HQMM, JAX-based) to detect latent market regimes, benchmark against classical baselines (`hmmlearn`, Hamilton Markov-switching), then use detected regimes as a risk-sizing overlay on a trading strategy.

## Source of truth

`PLAN.md` is the authoritative research design doc — math derivations, candidate comparisons, benchmark grid, dataset/backtest discipline, open decisions. Read it before making design changes. Keep it updated as decisions are made or reversed; don't let this file and PLAN.md drift apart on anything math/methodology-related — CLAUDE.md is for how to work in the repo, PLAN.md is for what/why.

## Status

Core pipeline implemented and tested (see layout below): real market data ingestion (`data.binance.vision` aggTrades archives, `data fetch-binance`), phasor math, frac-diff + minimum-d search, dollar bars, VQ discretization, synthetic regime-switching data generator, classical baselines (Gaussian/categorical HMM, Hamilton, no-regime), HQMM (JAX Kraus operators), CUSUM structural breaks, 2x2 ablation-grid benchmark, backtest overlay (CPCV/embargo, deflated Sharpe, PBO), full Typer CLI, and a matplotlib paper style + figure commands. Not yet done: the paper itself, and running the pipeline end-to-end on real BTC/USDT data at PLAN.md's full 2020-2025 scale (the ingestion path itself is implemented and tested; the rest of the pipeline so far has only been validated on synthetic ground truth + unit/property tests).

## Stack

- Python >=3.12, managed with `uv` (not pip/poetry/conda directly)
- `ruff` for lint/format
- `pytest` for tests
- `polars` for bar construction / data wrangling (tick-level volume, chosen over pandas for throughput)
- `jax` / `optax` for the HQMM (complex dtypes, autodiff, `expm` for unitary/Kraus parameterization)
- `hmmlearn` for the classical-HMM baselines
- `typer` for CLI
- `matplotlib` for all paper figures (no seaborn/plotly for paper output — matplotlib only, for full control over publication styling)

Commands once dependencies are added:
- `uv add <pkg>` / `uv add --dev <pkg>`
- `uv run ruff check .` / `uv run ruff format .`
- `uv run pytest`

## Layout (once code starts)

- `src/fin_regime_phasor/` — installable package (data ingestion, bar construction, phasor features, frac-diff, VQ discretization, HQMM, classical baselines, backtest overlay)
- `src/fin_regime_phasor/data/` — `data.binance.vision` aggTrades ingestion (`binance.py`), producing the `timestamp`/`price`/`quantity` schema `bars.dollar_bars` consumes
- `src/fin_regime_phasor/cli/` — Typer app; one sub-command module per canonical script (bar building, feature extraction, frac-diff search, HQMM training, baseline fitting, backtest run, etc.), all registered onto a single root Typer app as sub-commands
- `tests/` — pytest, mirrors package structure; prioritize property/numerical tests on the phasor math (e.g. Weierstrass-identity closed form vs. direct `sin`/`cos`/`arctan` must match)
- `notebooks/` — exploratory analysis, not imported by package code
- `data/` — raw/processed market data, gitignored entirely; regenerated via pipeline scripts/config, never committed

## CLI

No standalone scripts (`python foo.py`) for anything canonical/repeatable — every runnable step (data download/bar building, feature extraction, frac-diff search, HQMM/baseline training, backtest) is a Typer sub-command registered on one root app, invoked as `uv run fin-regime-phasor <subcommand>`. One-off/throwaway exploration can stay in `notebooks/`, but anything meant to be rerun or reused graduates into a sub-command. Wire the entrypoint via `[project.scripts]` in `pyproject.toml`.

## Plotting standards (matplotlib, publication quality)

All figures destined for the paper must clear top-tier-venue bar, not default matplotlib look:

- **Vector output**: save as PDF (`savefig(..., format="pdf", bbox_inches="tight")`), never PNG/raster for line/scatter/bar plots — PNG only acceptable for genuinely dense scatter/heatmap data where vector file size is prohibitive, and then at ≥300 DPI.
- **Shared style, not per-plot tweaking**: one `matplotlib.style` sheet (e.g. `src/fin_regime_phasor/plotting/paper.mplstyle`) applied via `plt.style.use(...)` in every figure-producing sub-command — consistent fonts, sizes, line widths, colors across the whole paper, no one-off rcParams scattered in notebooks.
- **Fonts match the paper body**: serif family consistent with the LaTeX document (Computer Modern or `text.usetex = True` if BasicTeX has the needed packages), math rendered via mathtext/usetex — not the matplotlib default sans-serif.
- **Sizing**: figure dimensions set to match LaTeX column/textwidth (compute from the document's actual `\textwidth`, don't eyeball it), so figures aren't rescaled (and re-rasterized/distorted) at include time.
- **Color**: colorblind-safe, perceptually uniform palettes (e.g. `viridis`/`cividis` for continuous data, `tab10`/Okabe-Ito for categorical/regime labels) — regime-overlay plots in particular need distinguishable-in-grayscale colors since print/grayscale rendering is common for reviewers.
- **Minimal ink**: no default gridlines/heavy spines/legend boxes unless they carry information; axis labels and units always present; no chart titles inside the figure (captions live in LaTeX, not baked into the image).
- **Reproducibility**: every figure is produced by a named CLI sub-command (see CLI section) taking the pipeline's output as input, so any figure can be regenerated byte-for-byte from `data/` + code, never hand-edited after export.

## Research discipline (carried from PLAN.md — enforce in code, not just docs)

- **No look-ahead leakage**: anything fit on data (frac-diff order search, VQ codebook, `k`, hidden-state count, HMM/HQMM params) must fit on training folds only. Hyperparameter search uses purged K-fold / CPCV with embargo (AFML ch. 7, 12).
- **Held-out test window (2026-01-01 → present) touched once**, at the very end, no tuning against it.
- **Frac-diff** (`FFD`, fixed-width window per AFML §5.4) applied separately to `ln(P)` (feeds phase) and to `sigma` (feeds magnitude) — independent minimum-`d` searches, do not assume `d=1` or that both series share a `d*`.
- **Magnitude/phase computed independently before combining into `z`** — never frac-diff or otherwise transform the complex phasor directly, since that mixes magnitude and phase history across lags.
- Benchmark comparisons must isolate representation (raw vs. phasor) from mechanism (classical vs. quantum) — see the 2x2 ablation grid in PLAN.md; don't report a single classical-vs-quantum number as if it settles both.
- Validate the HQMM implementation on synthetic ground-truth regime-switching data before trusting output on real market data.

## Conventions

- Keep variable names aligned with PLAN.md's math notation where practical (`sigma`, `theta`, `R`, `k`, `z`) rather than generic names — this is a math-heavy codebase and symbol continuity matters for readability against the derivations.
- No code comments explaining *what* code does; only *why*, for non-obvious constraints (e.g. why a closed-form rational identity is used instead of calling `arctan`/`sin`/`cos`).
